# 如何驗證改稿效果

這個 repo 有三層不同的檢查。結構通過不代表模型改稿通過，個別案例通過也不代表其他模型或所有文本都通過。

| 檢查 | 能確認什麼 | 無法確認什麼 |
|---|---|---|
| `validate_repo.py`、官方 skill validator | metadata、版本、模式、文件、授權與 corpus 結構 | 模型是否遵守規則、文字是否自然 |
| `check_forward_outputs.py` | 實際輸出的記錄格式、版本、案例 ID、逐字保護片段與覆蓋率 | 片段的歸因、否定、數值對應或輸出模式是否正確 |
| 獨立編輯審閱 | 語意、聲音、文體、任務範圍與改稿品質 | 作者身分、AI 生成機率或偵測器通過率 |

## 執行與審閱分開

1. 從 [forward corpus](../tests/forward_cases.json) 選擇同時涵蓋清理與保留的案例，長文修改至少包含一組長文。
2. 執行 agent 只讀當次 `SKILL.md`、案例 `request` 和 `input`。不要提供預期答案、失敗猜測或審閱結論。
3. 保存完整原始回應，不剪掉錯誤段落或修改後冒充原輸出。先把 `review.status` 設為 `pending`。
4. 另一位編輯或 agent 對照原文，逐項核對下表及案例的 `must_preserve`、`must_avoid`、`success_checks`，記錄 pass／fail 的依據與審閱者身分。agent 審閱不能寫成真人已評。
5. 執行離線 checker。若修改 skill，使用新版本重跑受影響案例，不只改舊結果的版本號。

| 審閱面向 | 通過條件 |
|---|---|
| 事實與關係 | 主體、數值／單位對應、條件、否定、歸因、因果、比較方向、時間與計畫狀態保留；未補新主張。 |
| 內容與文體 | 各段獨立資訊與功能保留；沒有把改寫做成摘要、把教學去重，或把評論洗成中立公告。 |
| 聲音 | 保留原視角、立場與已有的語氣；樣本只提供風格，沒有搬入故事或實測數字。 |
| 任務範圍 | 只審稿沒有整篇重寫；只給正文沒有聊天框架；自然稿沒有為交差硬改。 |
| 清理效果 | 能指出具體改善的空話、重複或表達問題；沒有以新增人設、怪標點、刻意碎句換掉原本的模板。 |

任一事實或範圍錯誤都是 fail，不能靠其他面向較好抵銷。需要修改的案例必須有實際改善；應保留的案例則允許 no-op。沒有足夠判斷依據就維持 pending。

## 結果格式與重跑

JSON 記錄包含 `schema_version: 1`、`skill_version`、`run` 和 `outputs`。`run` 需有 `date`（YYYY-MM-DD）、`executor`、`setup`；寫明實際模型或 agent 環境、案例如何提供、是否共享上下文，以及由誰審閱。無法取得精確模型 ID 時就寫未取得。

每個 output 需包含 `case_id`、完整 `output`，以及 `review` 的 `status`（pass／fail／pending）與 `notes`。可參照本次的 [實際結果](../tests/results/2026-10-08-pro6.json)。

```bash
python3 scripts/check_forward_outputs.py tests/results/2026-10-08-pro6.json
```

退出碼 0 只表示提交案例的記錄審閱為 pass，且逐字保護片段完整；1 表示 pending、fail 或片段遺失；2 表示版本、格式、ID 等錯誤，無法可靠檢查。報告會列出實際覆蓋與未跑案例，不將部分通過寫成全 corpus 通過。

`protected_literals` 只用於明確不能改的引語、命令、URL、標籤或完整受保護區塊，且每項必須存在於 input。`must_preserve` 的語意描述由編輯審閱，不能拿來作逐字比對；同義表達可以保留語意，也可能改壞歸因。即使所有片段都出現，仍需確認它們位於正確的主張中。

## 本次測試的限制

2026-10-08 初輪由兩個獨立 delegated agents 執行 16 組案例，每組 agent 內的案例共享上下文。root agent 審閱後有 1 組失敗，保存於 [初輪記錄](../tests/results/2026-10-08-pro6-initial.json)；補強動作保留規則後，由第三個獨立 agent 重跑該案例。最後澄清輸出偏好不改變任務模式，由第四個獨立 agent 重跑兩組審稿案例。最終記錄包含三組重跑與其餘 13 組未受影響的原始輸出。執行者未取得預期答案或審閱規則，root agent 另行核對完整輸出，精確模型 ID 未取得。這是一次 agent 行為抽查，不是多模型、多次抽樣或真人盲評，也沒有證明勝過競品。

checker 本身以 unittest 檢查片段遺失、版本不符、重複／未知案例、pending 與部分覆蓋等失敗；這些測試不算模型改稿案例。
